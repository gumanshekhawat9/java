# Java RMI: Remote Method Invocation

A Java RMI application in which a client calls the `add()` method of an object that runs in a different JVM (the server).

## Aim
To develop a simple Java RMI application in which a client invokes a method of a remote object to add two numbers.

## What is RMI?
RMI lets an object in one JVM invoke methods on an object in another JVM, possibly on another computer, with ordinary method-call syntax:
```java
int result = obj.add(10, 20);   // obj lives in the server JVM
```

## Architecture
```
                RMI Registry (name "Add")
                  ^ bind            ^ lookup
                  |                 |
   SERVER JVM ----+                 +---- CLIENT JVM
   MyRemote object <---- Stub <---- obj.add(10, 20)
        |                              ^
        +---------- result = 30 -------+
```

| Component | Role |
|-----------|------|
| Remote Interface (`MyInterface`) | Declares the methods that can be called remotely; extends `Remote` |
| Remote Object (`MyRemote`) | Implements the interface; extends `UnicastRemoteObject` |
| Server | Creates the object and registers it under the name `Add` |
| RMI Registry | Naming service that maps a name to a remote object |
| Client | Looks up `Add` and calls `add()` |
| Stub | Client-side proxy that sends the call over the network |

In modern Java, stubs and server-side dispatch are generated by the RMI runtime, so no manual stub or skeleton classes are needed.

## `bind()` vs `rebind()`
`bind()` fails if the name is already registered. `rebind()` registers the name or replaces an existing binding, which is convenient for lab work.

## How to Run
From the `Exp_5_RMI` folder, compile once:
```
javac -d out src/MyInterface.java src/MyRemote.java src/Server.java src/Client.java
```
Terminal 1 (start first, keeps running):
```
java -cp out Server
```
Terminal 2:
```
java -cp out Client
```
The server starts the RMI registry itself, so a separate `rmiregistry` is not needed.

## Expected Output
Server:
```
Server is ready...
```
Client:
```
Result = 30
```

## Advantages
- Remote calls use normal Java method syntax
- Object-oriented, supports distributed Java applications
- Hides the network communication details

## Limitations
- Mainly for Java-to-Java communication
- Remote calls are slower than local calls and can fail with network errors
- Client and server must share the same remote interface

## Requirements
- JDK 8 or higher
